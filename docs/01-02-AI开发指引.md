# AI 开发指引

本文档为 AI 编码工具（如 Cursor、Copilot、Gemini 等）提供快速上下文概要，帮助 AI 在最短时间内理解项目结构并开始编写代码。

## 项目一句话概要

Next.js 16 + Hono 前后端一体化后台管理脚手架，MySQL + Drizzle ORM，Mantine UI，Zod 类型安全，RBAC 权限控制。

## 编码模式速查

### 新增 API 路由

```ts
// 1. 定义 Zod Schema → src/server/routes/{resource}/dtos.ts
// 2. 实现路由 → src/server/routes/{resource}/index.ts
// 3. 注册路由 → src/server/route-defs.ts (.route('/xxx', xxx))
```

#### 路由中的校验器

路由中 **必须** 使用项目封装的 `zValidator`，而非直接使用 `@hono/zod-validator`：

```ts
// ✅ 正确 — 使用项目封装版本，统一校验错误格式与 debug 日志
import { zValidator } from "@/server/utils/validator";

// ❌ 错误 — 不要直接导入原始包
import { zValidator } from "@hono/zod-validator";
```

项目封装版本的作用：
- 统一将校验失败转换为 `ValidationError`，格式与全局错误处理器对齐
- 在 debug 级别打印原始请求数据和校验失败原因，方便本地排查问题

#### 批量生成权限 + 审计中间件

对于标准 CRUD 路由，推荐使用 `createCrudMiddlewares` 工厂函数批量生成每个操作的权限检查和审计日志中间件，无需手写重复代码。该工厂函数位于 `src/server/routes/shared/crud/router-factory.ts`。

### 新增 Service

```ts
// src/server/services/system/{resource}/{resource}.service.ts
// 规则: 错误用 throw AppError 子类，不用 return
// 数据库错误用 catch + throw handleDatabaseError(err)
```

### 新增前端 Hooks

```ts
// src/hooks/queries/resources/{resource}.ts
// 用 createResource<TList, TDetail, TCreate, TUpdate, TQuery>({...})
// 自动生成 useList / useDetail / useCreate / useUpdate / useDelete
```

### 响应方式

```ts
return R.ok(c, data); // 200
return R.ok(c, data, "获取成功"); // 200, 带消息
return R.success(c, "操作成功"); // 200, data: null
return R.fail(c, "操作失败"); // HTTP 200，业务错误码 BAD_REQUEST
// 注意: R.fail 返回 HTTP 200，响应体 code 字段为 'BAD_REQUEST'，这是业务层错误码设计，非 HTTP 错误
// 错误: throw new NotFoundError('资源', id)
// 错误: throw new BusinessError('消息', ErrorCode.XXX)
```

### 权限中间件

```ts
requireAuth; // 需要登录
requirePermission("module:res:op"); // 需要特定权限
auditLog({ module, operation, description }); // 审计日志
```

## 关键约束

1. **中间件顺序不可更改** — `src/server/setup/middlewares.ts` 中间件的注册顺序严格固定
2. **R 工具方法需要传入 Context** — 所有 R 方法第一个参数必须是 `c: Context`
3. **Service 层用 throw 报告错误** — 不要在 Service 中 `return R.xxx()`
4. **Zod Schema 是唯一事实来源** — 类型从 Schema 推导，不手写 interface
5. **新路由必须注册到 route-defs.ts** — 否则 RPC Client 类型不生效
6. **权限命名: `{模块}:{资源}:{操作}`** — 如 `system:admin:list`
7. **超级管理员权限为 `['*']`** — 匹配所有权限检查
8. **公开路径在 middlewares.ts 中配置** — 修改 `PUBLIC_PATHS` Set 集合
9. **UI 容器选举标准** — 搜索/过滤区用 `Paper` (withBorder), 列表容器与统计卡片用 `Card` (withBorder), 弹窗内分组禁用 `withBorder`。
