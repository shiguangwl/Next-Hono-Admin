# 架构设计

## 整体架构

本项目采用 **前后端一体化** 架构，Next.js App Router 负责页面渲染，Hono 运行在 Next.js Route Handler 内处理所有 `/api/*` 请求。

```
┌──────────────────────────────────────────────────────┐
│                     浏览器                            │
│                                                      │
│  ┌──────────────────┐    ┌─────────────────────────┐ │
│  │   React 页面      │    │   Hono RPC Client       │ │
│  │   (Mantine UI)   │    │   (类型安全 HTTP 调用)    │ │
│  │   + React Query  │◄──►│   hc<AppType>(baseUrl)   │ │

└──────────────────────────────────────┼───────────────┘
```

## 请求生命周期

以 `GET /api/admins?page=1&pageSize=20` 为例：

```
1. 浏览器发起请求
   → Next.js Edge Middleware（middleware.ts）：API 路径直接放行

2. Next.js Route Handler
   → src/app/api/[[...route]]/route.ts：转发给 Hono app

3. Hono 中间件管线
   ① requestContextMiddleware：生成 requestId（UUID），设置到 Context + 响应头 + AsyncLocalStorage
   ② requestLoggerMiddleware：在响应结束后记录结构化请求日志
   ③ corsMiddleware：处理 CORS 跨域
   ④ csrfMiddleware：CSRF 防护校验
   ⑤ apiRateLimit：全局 API 速率限制（100次/分，超限返回 429）
   ⑥ sessionAuth：优先读取 HttpOnly Cookie，兼容 Authorization Bearer Token → 查 `sys_admin_session` → c.set('admin') / c.set('sessionId')
   ⑦ loadPermissions：根据 admin.adminId 加载权限列表（带内存缓存），c.set('permissions', [...])

4. 路由级中间件
   → requireAuth：断言 c.get('admin') 非 null
   → requirePermission('system:admin:list')：校验权限

5. Route Handler
   → zValidator('query', AdminQuerySchema)：Zod 校验查询参数，若失败则抛出 `ValidationError`
   → 调用 getAdminList(query)

6. Service 层
   → getAdminList 组装 Drizzle 查询 → 返回分页结果

7. 响应
   → return R.ok(c, result)
   → requestLoggerMiddleware 记录请求结束（耗时、状态码）
   → 响应: { code: 'OK', data: { items: [...], total: 100 } }
```

## 类型安全链路

Zod Schema 是唯一事实来源，贯穿整个请求-响应链路：

```
Zod Schema (dtos.ts)
    │
    ├──► 请求校验：zValidator('json', CreateAdminInputSchema)
    │
    ├──► TypeScript 类型：type CreateAdminInput = z.infer<typeof CreateAdminInputSchema>
    │
    ├──► RPC Client 类型：AppType 通过 route-defs.ts 导出，客户端自动获得类型约束
    │
    └──► OpenAPI 文档（如果使用 @hono/zod-openapi）
```

**RPC Client 类型安全示意：**

```ts
// src/server/route-defs.ts — 服务端导出路由类型
export const routes = new Hono<Env>()
  .route("/auth", auth)
  .route("/admins", admins);
// ...

export type AppType = typeof routes;

// src/lib/client.ts — 客户端使用类型
import type { AppType } from "@/server/route-defs";
const client = hc<AppType>(`${baseUrl}/api`);

// 客户端调用自动获得类型提示
const res = await client.admins.$get({ query: { page: "1" } });
//                       ~~~~~~ 自动补全路由
//                                        ~~~~~ 类型约束查询参数
```

## Context 与请求级数据

### Hono Context Variables

```ts
// src/server/context.ts
export interface Variables {
  requestId: string; // 请求追踪 ID
  admin: AdminPayload | null; // 当前登录用户（未登录为 null）
  sessionId: number | null; // 当前会话 ID
  permissions: string[] | null; // 用户权限列表
}

export interface Env {
  Bindings: Bindings; // 外部注入的绑定（本项目为空 Record）
  Variables: Variables;
}
```

### AsyncLocalStorage

项目使用两个 AsyncLocalStorage 实例：

| 位置                         | 用途                                                 | 依赖中间件                 |
| ---------------------------- | ---------------------------------------------------- | -------------------------- |
| `src/lib/logging/context.ts` | 存储 RequestContext（requestId），供 Logger 自动附加 | `requestContextMiddleware` |

## 统一响应格式

### 成功响应

```json
{
  "code": "OK",
  "data": { ... },
  "message": "可选的提示消息"
}
```

### 错误响应

```json
{
  "code": "UNAUTHORIZED",
  "message": "未登录或登录已过期",
  "details": {},
  "requestId": "xxx-xxx"
}
```

### R 工具对象（`src/server/utils/response.ts`）

```ts
// 成功响应（所有方法都需要传入 c: Context）
return R.ok(c, data); // 200  { code: 'OK', data }
return R.ok(c, data, "获取成功"); // 200  { code: 'OK', data, message }
return R.success(c, "操作成功"); // 200  { code: 'OK', data: null, message }
return R.fail(c, "操作失败"); // 200  { code: 'BAD_REQUEST', data: null, message }（业务层错误，HTTP 状态码仍为 200）

// 错误响应：建议优先使用 throw AppError 子类，由全局处理器捕获
throw new UnauthorizedError("未登录或登录已过期");
throw new ForbiddenError("无权限执行此操作");
throw new NotFoundError("资源", id);
```

> **关键约束**：`R` 所有方法的第一个参数必须是 Hono Context `c`。

## 应用初始化流程

```ts
// src/server/app.ts
const app = new Hono<Env>();

setLogRecorder(createOperationLog); // 注入审计日志写入函数
setupMiddlewares(app); // 注册中间件管线（顺序严格固定）
app.get(HEALTH_CHECK_PATH, (c) => c.json({ status: "ok" })); // 健康检查端点 GET /api/health
app.route("/api", routes); // 挂载所有路由到 /api
setupErrorHandlers(app); // 注册全局错误处理器 + 404 处理器
```

```ts
// src/instrumentation.ts（Next.js 启动钩子）
export async function register() {
  if (process.env.NEXT_RUNTIME === "nodejs") {
    // 1. OpenTelemetry 初始化（必须最先执行，在 HTTP/DB 模块 import 前 patch）
    const { initTelemetry } = await import("@/lib/telemetry");
    await initTelemetry();

    // 2. 数据库初始化（按环境变量可选执行迁移和种子）
    const { ensureDatabaseInitialized } = await import("@/db");
    await ensureDatabaseInitialized();

    // 3. 后台任务：启动会话清理定时任务

    startSessionCleanupTask();
  }
}
```

## RBAC 权限中间件

权限中间件位于 `src/server/middleware/rbac.ts`，提供三种粒度的权限校验工厂：

```ts
// 单一权限（最常用）
requirePermission("system:admin:list")

// 任一满足（拥有其中一个权限即可通过）
requireAnyPermission(["system:admin:list", "system:admin:edit"])

// 全部满足（必须同时拥有所有权限）
requireAllPermissions(["system:admin:edit", "system:admin:delete"])
```

> 超级管理员（id=1）的权限列表为 `['*']`，三种变体均直接放行。未登录时抛出 `UnauthorizedError`，权限不足时抛出 `ForbiddenError`。
