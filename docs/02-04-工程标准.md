# 工程标准

> 极度严谨的代码质量、严格的规模控制以及绝对的安全标准。

## 1. 代码规模控制 (Scale Control)

为了保持系统的可维护性和低认知负担，本项目强制执行以下规模指标：

| 指标         | 推荐值 | 🚨 硬上限 | 重构建议                            |
| :----------- | :----- | :-------- | :---------------------------------- |
| **文件行数** | 200 行 | 300 行    | 按职责拆分子模块或提取公共逻辑      |
| **函数行数** | 30 行  | 50 行     | 提取子函数（Extract Function）      |
| **参数数量** | 3 个   | 5 个      | 封装为配置对象 (Options Object)     |
| **嵌套层级** | 3 层   | 4 层      | 使用卫语句 (Guard Clauses) 提前返回 |

## 2. 编码规范 (Coding Standards)

### 2.1 风格工具

- **Biome**: 替代 ESLint + Prettier，负责 Lint、格式化及 Import 排序。
- **强制要求**: 提交代码前必须通过 `pnpm lint:fix`。

### 2.2 核心准则

- **单一职责**: 每个模块/函数仅做一件事情。
- **DRY 原则**: 严禁硬编码（魔法数字/字符串），重复逻辑必须提取。
- **卫语句优先**: 逻辑分支应优先处理错误/边界情况，减少 `else` 嵌套。
- **自解释命名**: 变量名应描述其实际业务含义，减少不必要的背景注释。

## 3. Git 提交约定 (Commit Convention)

遵循 **Conventional Commits** 规范：

- `feat`: 新功能 (feature)
- `fix`: 修补 bug
- `docs`: 文档 (documentation)
- `style`: 格式 (不影响代码运行的变动，例如空格、分号等)
- `refactor`: 重构 (即不是新增功能，也不是修改 bug 的代码变动)
- `test`: 增加测试
- `chore`: 构建过程或辅助工具的变动 (例如，更新依赖、修改构建脚本)
- `perf`: 性能优化
- `revert`: 回滚之前的 commit
- `build`: 影响构建系统或外部依赖项的更改（示例范围：gulp、broccoli、npm）
- `ci`: 对 CI 配置文件和脚本的更改（示例范围：Travis、Circle、BrowserStack、SauceLabs）
