# 认证与权限

## 认证流程

### 登录流程

```
前端 LoginForm                → POST /api/auth/login { username, password }
  ↓
服务端 auth/index.ts
  ↓ loginRateLimit（限流检查）
  ↓ zValidator 校验参数
  ↓ 调用 login() Service
  ↓
  auth.service.ts
  ├─ findAdminByUsername(username)
  ├─ verifyPassword(input, admin?.password ?? TIMING_DEFENSE_HASH)
  │   └─ 无论用户是否存在，均执行 bcrypt 校验，消除时序差异（防用户名枚举）
  ├─ 检查 admin.status === 1（账号是否启用）
  ├─ 并发执行（Promise.all）：
  │   ├─ createAdminSession({ adminId, ip, userAgent })
  │   │   ├─ createSessionToken()           // randomBytes(32).toString('base64url')
  │   │   ├─ hashSessionToken(token)        // SHA-256，仅存储哈希
  │   │   └─ insert sys_admin_session       // 写入服务端会话表
  │   └─ getGrantedMenus(admin.id)          // 查询已授权菜单（含权限字段）
  ├─ updateAdminLoginMetadata(admin.id, ip)  // 更新登录 IP + 时间
  ├─ extractPermissions(grantedMenus)        // 从菜单中提取权限列表
  └─ extractMenuTree(grantedMenus)           // 构建菜单树
  ↓
  auth/index.ts
  ├─ setSessionCookie(c, sessionToken)       // 写入 HttpOnly Cookie
  └─ 返回: { sessionToken, admin, permissions, menus }
  ↓
前端 useAuth.login()
  ├─ 存储 admin / permissions / menus 到 Zustand Store
  └─ 跳转到 /dashboard
```

### 认证状态初始化

```ts
// src/app/providers.tsx → AuthInitializer
// 应用启动时，通过当前 Cookie 会话调用 GET /api/auth/info 刷新认证状态
useEffect(() => {
  if (!initialized) refreshAuth();
}, [initialized, refreshAuth]);
```

```
refreshAuth() 流程：
  ├─ 直接调用 GET /api/auth/info
  │   ├─ 成功 → 更新 admin/permissions/menus
  │   └─ 失败（401/403） → 清空内存中的认证状态，设为未认证
  └─ 设置 initialized=true
```

### 会话管理

| 方面 | 实现 |
| ---- | ---- |
| 生成 | `createSessionToken()` 使用 `randomBytes(32).toString('base64url')` 生成 32 字节随机 token |
| 存储 | 浏览器端使用 `HttpOnly` Cookie；服务端仅保存 `tokenHash`（SHA-256 哈希） |
| 验证 | `sessionAuth` 查 `sys_admin_session`，校验未过期、未撤销、管理员仍启用 |
| 传递 | 浏览器请求自动携带 Cookie；非浏览器场景可兼容 `Authorization: Bearer <token>` |
| 过期 | 由 `SESSION_TTL_DAYS` 控制，默认 `7` 天 |
| Cookie 名称 | `SESSION_COOKIE_NAME`，默认 `auth_session` |

### 会话管理函数

| 函数 | 说明 |
| ---- | ---- |
| `createAdminSession(input)` | 创建会话，返回明文 token |
| `authenticateSessionToken(token)` | 验证 token，返回 `{ admin, sessionId }` 或 `null` |
| `revokeSessionById(sessionId)` | 按 sessionId 撤销单个会话 |
| `revokeSessionToken(token)` | 按明文 token 撤销会话 |
| `revokeSessionsByAdminId(adminId)` | 撤销某管理员的全部会话（如禁用账号时调用） |
| `deleteExpiredSessions()` | 删除已过期或已撤销的会话记录，返回受影响行数 |

### 会话认证中间件

`session-auth.ts` 使用工厂模式实现，对外暴露 `createSessionAuth` 和默认实例 `sessionAuth`。

```ts
// src/server/middleware/session-auth.ts

// collectTokenCandidates：按优先级收集 token 候选列表
// 先收集 Cookie token，再收集 Bearer token
function collectTokenCandidates(c: Context<Env>): TokenCandidate[]

// createSessionAuth：工厂函数，支持依赖注入 resolveSession（便于测试）
// WHY: cookie 验证失败时回退到 Bearer，避免失效 cookie 屏蔽有效 Bearer token
export function createSessionAuth(resolveSession: SessionResolver) {
  return createMiddleware<Env>(async (c, next) => {
    const candidates = collectTokenCandidates(c)

    if (candidates.length === 0) {
      clearAuthContext(c)
      return next()
    }

    for (const { token, fromCookie } of candidates) {
      const session = await resolveSession(token)
      if (session) {
        c.set('admin', session.admin)
        c.set('sessionId', session.sessionId)
        return next()
      }
      // Cookie 验证失败时清除无效 Cookie，再尝试 Bearer
      if (fromCookie) {
        clearSessionCookie(c)
      }
    }

    clearAuthContext(c)
    return next()
  })
}

// 默认实例，使用 authenticateSessionToken 作为 resolver
export const sessionAuth = createSessionAuth(authenticateSessionToken)

// requireAuth: 断言已认证，否则 throw UnauthorizedError
export const requireAuth = createMiddleware<Env>(async (c, next) => {
  if (!c.get('admin')) throw new UnauthorizedError();
  return next();
});
```

### 登出路由

```ts
// POST /auth/logout
// 通过 sessionId 或 cookieToken 撤销会话，并清除客户端 Cookie
.post('/logout', loginRateLimit, async (c) => {
  const sessionId = c.get('sessionId')
  const cookieToken = getCookie(c, env.SESSION_COOKIE_NAME)

  if (sessionId) {
    await revokeSessionById(sessionId)
  } else if (cookieToken) {
    await revokeSessionToken(cookieToken)
  }

  clearSessionCookie(c)
  return R.success(c, '登出成功')
})
```

## RBAC 权限系统

### 数据模型

```
管理员 (sys_admin)
   ↓ 多对多
角色 (sys_role)          ← sys_admin_role 关联表
   ↓ 多对多
菜单权限 (sys_menu)      ← sys_role_menu 关联表
   └─ permission 字段    → 如 'system:admin:list'
```

### 权限加载

`rbac.ts` 使用工厂模式实现，`createLoadPermissions` 接受 `fetchPermissions` 函数作为依赖注入参数。

```ts
// src/server/middleware/rbac.ts

/**
 * 工厂函数：创建加载权限中间件（支持依赖注入，便于测试）
 */
export function createLoadPermissions(fetchPermissions: (adminId: number) => Promise<string[]>) {
  return createMiddleware<Env>(async (c, next) => {
    const admin = c.get('admin')

    if (!admin) {
      c.set('permissions', null)
      return next()
    }

    // 超级管理员短路：直接设置 ['*']，跳过数据库查询
    if (admin.adminId === SUPER_ADMIN_ID) {
      c.set('permissions', ['*'])
      return next()
    }

    // 使用缓存获取权限（TTL 5 分钟，最大缓存条目 1000）
    const permissions = await getCachedPermissions(admin.adminId, fetchPermissions)
    c.set('permissions', permissions)

    return next()
  })
}

/**
 * 默认实例：使用 getAdminPermissions 作为数据源
 * loadPermissions = createLoadPermissions(getAdminPermissions)
 */
export const loadPermissions = createLoadPermissions(getAdminPermissions)
```

### 权限校验中间件

```ts
// 校验单个权限
requirePermission("system:admin:list");

// 校验任一权限通过即可
requireAnyPermission(["system:admin:update", "system:admin:delete"]);

// 校验全部权限都通过
requireAllPermissions(["system:admin:list", "system:admin:query"]);
```

**内部逻辑（权限检查内联在各中间件中）：**

- 若 `permissions` 包含 `'*'`（超级管理员），直接放行
- 否则检查 `permissions` 数组中是否包含所需权限字符串

> [!NOTE]
> 权限检查逻辑直接内联在 `requirePermission` / `requireAnyPermission` / `requireAllPermissions` 中间件内部，不存在独立的 `checkPermission` 函数。

### 权限命名规范

```
格式: {模块}:{资源}:{操作}

CRUD 标准操作：
  system:admin:list      — 列表查询
  system:admin:query     — 详情查询
  system:admin:create    — 创建
  system:admin:update    — 更新
  system:admin:delete    — 删除

扩展操作（语义化命名）：
  system:admin:resetPwd    — 重置密码
  system:admin:assignRole  — 分配角色
  system:role:assignMenu   — 分配菜单
  system:log:delete        — 删除日志
```

### 菜单类型与权限

| 菜单类型         | 代码 | 说明                           | permission 字段            |
| ---------------- | ---- | ------------------------------ | -------------------------- |
| 目录 (Directory) | `D`  | 侧边栏目录，不对应实际页面     | 通常不设置                 |
| 菜单 (Menu)      | `M`  | 侧边栏菜单项，对应页面         | 可选，用于菜单显示权限     |
| 按钮 (Button)    | `B`  | 按钮级权限标识，不显示在侧边栏 | **必填**，用于操作权限校验 |

### 菜单级 — 动态菜单树

侧边栏菜单根据用户权限动态渲染（来源于 `GET /api/auth/info` 返回的 `menus` 字段），无权限的菜单不会显示。

```tsx
const { hasPermission } = usePermission();
{
  hasPermission("system:admin:delete") && <DeleteButton />;
}
```

## 权限缓存策略

权限缓存独立封装在 `src/server/utils/permission-cache.ts`。

- 缓存 Key：`adminId`
- TTL：**5 分钟**（`CACHE_TTL = 5 * 60 * 1000`）
- 最大条目数：**1000**（`MAX_CACHE_SIZE = 1000`）；达到上限时淘汰最早插入的条目
- `getCachedPermissions(adminId, fetchPermissions)`：双参数，`fetchPermissions` 为依赖注入的数据源函数
- `invalidatePermissionCache(adminId)`：清除单个用户缓存
- `invalidateAllPermissionCache()`：清除所有缓存
- `getPermissionCacheSize()`：返回当前缓存条目数

修改用户角色后应主动调用 `invalidatePermissionCache(adminId)` 清除缓存。
