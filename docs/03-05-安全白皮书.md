# 安全白皮书

> 坚持安全零容忍红线，核心鉴权必须在后端完成。

## 1. 数据访问安全 (Data Access)

- **参数化查询**: 必须使用 Drizzle ORM 的模板字符串或自带方法，严禁任何形式的字符串拼接 SQL。
- **敏感字段保护**: Schema 定义中对于密码等敏感字段，在 DTO 返回阶段必须通过 Zod 进行剔除（Omit/Pick）。

## 2. 输入与输出防御 (Defense)

- **外部输入校验**: 所有来自 HTTP 请求的数据（Query, Body, Params）必须通过 `zValidator` 校验，禁止漏掉任何外部输入。校验失败返回结构化 `VALIDATION_ERROR`，不暴露原始 Zod 错误堆栈。
- **XSS 防御**: 前端 Mantine UI 默认进行转义，但在处理自定义富文本或原始 HTML 时，必须进行服务端清洗或校验。

## 3. 认证安全 (Authentication)

### 3.1 Session Token 生成与存储

- **生成**: `createSessionToken()` 使用 `randomBytes(32).toString('base64url')`，生成 256 位密码学安全随机 token。
- **哈希存储**: `hashSessionToken(token)` 使用 SHA-256 对 token 进行哈希，数据库（`sys_admin_session.tokenHash`）仅存储哈希值。即使数据库泄露，攻击者也无法还原明文 token。
- **传输**: 明文 token 仅在登录响应中返回一次（`sessionToken` 字段），后续通过 Cookie 携带，不再在响应体中出现。

### 3.2 Cookie 安全配置

| 属性 | 值 | 说明 |
| ---- | -- | ---- |
| `HttpOnly` | `true` | 禁止 JavaScript 访问，防御 XSS 窃取 Cookie |
| `SameSite` | `Strict` | 防御跨站请求伪造（CSRF） |
| `Secure` | 由 `COOKIE_SECURE` 环境变量控制 | HTTPS 环境下应设置为 `true`，仅通过加密连接传输 |
| 名称 | `SESSION_COOKIE_NAME`（默认 `auth_session`） | 可通过环境变量自定义 |
| 有效期 | `SESSION_TTL_DAYS` 天（默认 7 天） | 可通过环境变量调整，最大 30 天 |

### 3.3 密码安全

- 所有密码使用 **bcrypt** 哈希存储，严禁明文或弱哈希（MD5/SHA1）存储。
- `verifyPassword` 用于登录时的密码核验，使用 bcrypt 的恒定时间比较。

### 3.4 时序攻击防御

登录服务使用预计算 dummy hash（`TIMING_DEFENSE_HASH`）防止通过响应时间差异枚举用户名：

```ts
// auth.service.ts
// WHY: 预计算 dummy hash，使不存在用户也执行 verifyPassword，消除时序差异
const TIMING_DEFENSE_HASH = await hashPassword('timing-defense-dummy')

const passwordToCompare = admin?.password ?? TIMING_DEFENSE_HASH
const isValid = await verifyPassword(input.password, passwordToCompare)
```

无论用户名是否存在，都会执行一次 bcrypt 校验，确保响应时间无显著差异。

## 4. CSRF 防御 (CSRF Protection)

实现位于 `src/server/middleware/csrf.ts`，对所有非安全方法（`POST / PUT / PATCH / DELETE`）进行来源验证。

### 4.1 验证策略

1. **优先检查 `Origin` 头**: 存在 `Origin` 时，对其进行白名单或同源匹配。
2. **回退到 `Referer` 头**: `Origin` 缺失时，检查 `Referer`。
3. **两者均缺失**: 直接拒绝，抛出 `ForbiddenError`。

### 4.2 Origin / Referer 匹配规则

- **配置了 `CORS_ORIGINS` 白名单时**: 使用 `new URL(origin).origin` 提取标准化 origin 后，与白名单中每个条目进行**严格等值比较**。
- **未配置 `CORS_ORIGINS` 时**: 回退为动态同源匹配，将 `new URL(origin).host` 与请求的 `Host` 头对比。

### 4.3 防 Referer 前缀伪造

使用 `new URL(referer).origin` 提取后比较，而非字符串 `startsWith`，避免如下攻击：

```
http://trusted.com.attacker.tld  ← 使用 startsWith('http://trusted.com') 会误匹配
new URL(...).origin === 'http://trusted.com'  ← 严格等值，不会误匹配
```

### 4.4 环境变量配置

```env
# 多个来源用逗号分隔，留空则使用动态同源匹配
CORS_ORIGINS=https://admin.example.com,https://app.example.com
```

## 5. 速率限制 (Rate Limiting)

实现位于 `src/server/middleware/rate-limit.ts`，采用固定窗口算法，三级策略覆盖不同风险场景。

### 5.1 三级策略

| 中间件 | 时间窗口 | 最大请求数 | 适用场景 |
| ------ | -------- | ---------- | -------- |
| `apiRateLimit` | 1 分钟 | 100 次 | 全局通用 API 接口 |
| `loginRateLimit` | 1 分钟 | 5 次 | 登录、登出接口（防暴力破解） |
| `strictRateLimit` | 1 分钟 | 20 次 | 高风险写操作（如管理员删除、重置密码、分配角色/菜单） |

### 5.2 响应头

超出限制前，每次请求均携带以下响应头：

```
X-RateLimit-Limit: 5
X-RateLimit-Remaining: 3
X-RateLimit-Reset: 1712345678   ← Unix 时间戳，窗口重置时间
Retry-After: 42                 ← 仅超限时返回，单位秒
```

### 5.3 Key 生成

默认使用客户端 IP 作为限速 Key，优先读取 `X-Forwarded-For` 第一个 IP，回退到 `X-Real-IP`。

> [!WARNING]
> `X-Forwarded-For` 可被客户端伪造。生产部署时**必须**在反向代理（Nginx / Caddy）层配置可信 IP 覆盖（如 `set_real_ip_from`），否则攻击者可通过伪造此头绕过限速。

### 5.4 当前局限性

当前使用**进程内内存存储**（`Map`）：

- 进程重启后计数清零
- 多实例部署（PM2 cluster / 多 replica / 容器横向扩展）时各实例计数独立，实际限速效果降低

多实例场景下需改用 **Redis** 作为共享存储后端。

## 6. 会话安全 (Session Security)

### 6.1 会话验证

每次请求均校验以下条件，任一不满足则拒绝：

- `tokenHash` 匹配（SHA-256 哈希比对）
- `revokedAt IS NULL`（未被撤销）
- `expiresAt > NOW()`（未过期）
- `admin.status = 1`（账号未被禁用）

### 6.2 账号禁用自动撤销

禁用管理员账号时，应调用 `revokeSessionsByAdminId(adminId)` 撤销该账号的全部活跃会话，使其立即失效，无需等待 token 自然过期。

### 6.3 定期清理过期会话

`deleteExpiredSessions()` 删除所有已过期（`expiresAt <= NOW()`）或已撤销（`revokedAt IS NOT NULL`）的会话记录，可通过定时任务（`startSessionCleanupTask`）定期调用，防止会话表无限增长。

## 7. 审计日志安全 (Audit Log)

实现位于 `src/server/middleware/audit-log.ts`。

### 7.1 敏感字段过滤

`sanitizeBody` 函数在记录请求体之前自动将以下字段替换为 `'******'`（大小写不敏感）：

```
password、newpassword、oldpassword、token、accesstoken、refreshtoken、
secret、apikey、authorization、creditcard、ssn
```

嵌套对象会递归处理，确保多层结构中的敏感字段也被过滤。

### 7.2 异步写入

审计日志通过 `setImmediate` 异步写入，不阻塞请求响应链路。写入失败仅记录错误日志，不影响业务流程。

## 8. 认证与鉴权 (Auth & AuthZ)

- **后端核心校验**: 前端隐藏元素仅用于提升体验，核心权限检查必须在 Hono 中间件 `requirePermission` 及其变体中完成。
- **敏感操作审计**: 所有 `POST/PUT/DELETE` 等修改数据的操作，必须挂载 `auditLog` 中间件记录操作人及变更。

## 9. 敏感信息管理 (Secrets)

- **环境变量**: 密码、Token 密钥、数据库连接字符串严禁硬编码在代码中。
- **读取方式**: 统一通过 `src/env.ts` 读取，该模块使用 `@t3-oss/env-nextjs` 在启动时校验变量是否存在且格式正确，不合规则直接抛出异常，阻止服务启动。

## 10. 运维安全建议

### 10.1 HTTPS 与 Cookie Secure

生产环境必须启用 HTTPS，并将 `COOKIE_SECURE` 设置为 `true`：

```env
COOKIE_SECURE=true
```

未开启时，Cookie 可能通过 HTTP 明文传输，存在被中间人截获的风险。

### 10.2 反向代理配置

部署在 Nginx / Caddy 等反向代理后时：

- 配置 `set_real_ip_from` / `real_ip_header` 确保速率限制使用真实客户端 IP
- 设置 `CORS_ORIGINS` 明确指定允许的来源，避免依赖动态同源匹配

### 10.3 多实例部署

水平扩展时，需将速率限制存储迁移至 Redis，确保跨实例计数共享，防止单实例绕过策略。
