# 架构设计

## 整体架构

本项目采用 **前后端一体化** 架构，Next.js App Router 负责页面渲染，Hono 运行在 Next.js Route Handler 内处理所有 `/api/*` 请求。

```
┌──────────────────────────────────────────────────────┐
│                     浏览器                            │
│                                                      │
│  ┌──────────────────┐    ┌─────────────────────────┐ │
│  │   React 页面      │    │   Hono RPC Client       │ │
│  │   (Mantine UI)   │    │   (类型安全 HTTP 调用)    │ │
│  │   + React Query  │◄──►│   hc<AppType>(baseUrl)   │ │
│  │   + Zustand      │    │                         │ │
│  └──────────────────┘    └───────────┬─────────────┘ │
└──────────────────────────────────────┼───────────────┘
                                       │ HTTP /api/*
┌──────────────────────────────────────┼───────────────┐
│                   Next.js 服务端       │               │
│                                      ▼               │
│  ┌─────────────────────────────────────────────────┐ │
│  │ src/app/api/[[...route]]/route.ts                │ │
│  │ → 所有 /api/* 请求转发给 Hono app               │ │
│  └─────────────────────┬───────────────────────────┘ │
│                        ▼                             │
│  ┌──────── Hono 请求管线（自上而下） ────────┐        │
│  │                                          │        │
│  │  1. requestContextMiddleware             │        │
│  │     → 生成 requestId + AsyncLocalStorage  │        │
│  │                                          │        │
│  │  2. contextMiddleware                    │        │
│  │     → 存储 Hono Context（供 R 工具类使用）│        │
│  │                                          │        │
│  │  3. requestLoggerMiddleware              │        │
│  │     → Pino 结构化请求日志                 │        │
│  │                                          │        │
│  │  4. jwtAuth（公开路径跳过）               │        │
│  │     → 解析 Bearer Token                  │        │
│  │                                          │        │
│  │  5. loadPermissions                      │        │
│  │     → 加载并缓存用户权限                  │        │
│  │                                          │        │
│  │  6. 路由级中间件                          │        │
│  │     → requirePermission + auditLog       │        │
│  │                                          │        │
│  │  7. Route Handler                        │        │
│  │     → Zod 校验 → 调用 Service → R 响应   │        │
│  │                                          │        │
│  └────────────┬─────────────────────────────┘        │
│               ▼                                      │
│  ┌─────────────────────┐                             │
│  │    Service 层        │                             │
│  │    业务逻辑 + 查询    │                             │
│  └────────┬────────────┘                             │
│           ▼                                          │
│  ┌─────────────────────┐                             │
│  │  Drizzle ORM + MySQL │                             │
│  └─────────────────────┘                             │
└──────────────────────────────────────────────────────┘
```

## 请求生命周期

以 `GET /api/admins?page=1&pageSize=20` 为例：

```
1. 浏览器发起请求
   → Next.js Edge Middleware（middleware.ts）：API 路径直接放行

2. Next.js Route Handler
   → src/app/api/[[...route]]/route.ts：转发给 Hono app

3. Hono 中间件管线
   ① requestContextMiddleware：生成 requestId（UUID），设置到 Context + 响应头 + AsyncLocalStorage
   ② contextMiddleware：将 Hono Context 存入 AsyncLocalStorage（R 工具类依赖）
   ③ requestLoggerMiddleware：记录请求开始
   ④ jwtAuth：从 Authorization 头解析 Bearer Token → verifyToken → c.set('admin', payload)
   ⑤ loadPermissions：根据 admin.adminId 加载权限列表（带内存缓存），c.set('permissions', [...])

4. 路由级中间件
   → requireAuth：断言 c.get('admin') 非 null
   → requirePermission('system:admin:list')：校验权限

5. Route Handler
   → zValidator('query', AdminQuerySchema)：Zod 校验查询参数
   → 调用 getAdminList(query)

6. Service 层
   → getAdminList 组装 Drizzle 查询 → 返回分页结果

7. 响应
   → return R.ok(result)
   → requestLoggerMiddleware 记录请求结束（耗时、状态码）
   → 响应: { code: 'OK', data: { list: [...], total: 100 } }
```

## 类型安全链路

Zod Schema 是唯一事实来源，贯穿整个请求-响应链路：

```
Zod Schema (dtos.ts)
    │
    ├──► 请求校验：zValidator('json', CreateAdminInputSchema)
    │
    ├──► TypeScript 类型：type CreateAdminInput = z.infer<typeof CreateAdminInputSchema>
    │
    ├──► RPC Client 类型：AppType 通过 route-defs.ts 导出，客户端自动获得类型约束
    │
    └──► OpenAPI 文档（如果使用 @hono/zod-openapi）
```

**RPC Client 类型安全示意：**

```ts
// src/server/route-defs.ts — 服务端导出路由类型
export const routes = new Hono<Env>()
  .route("/auth", auth)
  .route("/admins", admins);
// ...

export type AppType = typeof routes;

// src/lib/client/index.ts — 客户端使用类型
import type { AppType } from "@/server/types";
const client = hc<AppType>(`${baseUrl}/api`);

// 客户端调用自动获得类型提示
const res = await client.admins.$get({ query: { page: "1" } });
//                       ~~~~~~ 自动补全路由
//                                        ~~~~~ 类型约束查询参数
```

## Context 与请求级数据

### Hono Context Variables

```ts
// src/server/context.ts
export interface Variables {
  requestId: string; // 请求追踪 ID
  admin: AdminPayload | null; // 当前登录用户（未登录为 null）
  permissions: string[] | null; // 用户权限列表
}

export type Env = { Variables: Variables };
```

### AsyncLocalStorage

项目使用两个 AsyncLocalStorage 实例：

| 位置                           | 用途                                                   | 依赖中间件                 |
| ------------------------------ | ------------------------------------------------------ | -------------------------- |
| `src/server/utils/response.ts` | 存储 Hono Context，供 `R` 工具类在任意位置获取 Context | `contextMiddleware`        |
| `src/lib/logging/context.ts`   | 存储 RequestContext（requestId），供 Logger 自动附加   | `requestContextMiddleware` |

## 统一响应格式

### 成功响应

```json
{
  "code": "OK",
  "data": { ... },
  "message": "可选的提示消息"
}
```

### 错误响应

```json
{
  "code": "UNAUTHORIZED",
  "message": "未登录或登录已过期",
  "details": {},
  "requestId": "xxx-xxx"
}
```

### R 工具类（`src/server/utils/response.ts`）

```ts
// 成功响应
return R.ok(data); // 200  { code: 'OK', data }
return R.ok(data, "获取成功"); // 200  { code: 'OK', data, message }
return R.created(entity); // 201  { code: 'OK', data, message: '创建成功' }
return R.success("操作成功"); // 200  { code: 'OK', data: null, message }

// 错误响应（建议优先使用 throw AppError 子类，由全局处理器捕获）
return R.fail("CUSTOM", "自定义错误"); // 400
return R.unauthorized(); // 401
return R.forbidden(); // 403
return R.notFound(); // 404
```

> **关键约束**：`R` 依赖 `contextMiddleware`，该中间件必须在路由之前注册。

## 应用初始化流程

```ts
// src/server/app.ts
const app = new Hono<Env>();

setupAuditLogger(); // 初始化审计日志记录器
setupMiddlewares(app); // 注册中间件管线（顺序严格固定）
setupRoutes(app); // 挂载所有路由到 /api
setupErrorHandlers(app); // 注册全局错误处理器 + 404 处理器
```

```ts
// src/instrumentation.ts（Next.js 启动钩子）
export async function register() {
  // 仅在 Node.js 运行时执行
  await ensureDatabaseInitialized(); // 自动迁移 + 种子（如配置启用）
  setErrorMonitor(new ConsoleMonitor()); // 设置错误监控
}
```
