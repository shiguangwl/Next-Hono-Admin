# 测试指南

> 通过自动化测试保障重构的安全性和逻辑的正确性。

## 1. 测试策略

本项目采用 **Vitest** 驱动测试体系；当前测试主要放置在根目录的 `tests/` 下，`vitest.config.ts` 同时支持扫描 `src/**/*.{test,spec}.{js,ts}`：

- **单元测试 (Unit)**: 针对 `services` 层和 `utils` 层的纯逻辑函数。
- **集成测试 (Integration)**: 模拟 Hono 请求流，验证从路由到数据库的完整链路。
- 当前测试以**单元测试**和**集成测试**为主，尚未单独维护数据库连接或迁移脚本级别的冒烟测试。

## 2. 目录结构

```bash
tests/
├── lib/                         # 共享工具类测试
│   ├── auth/                    # 认证工具（session-token 等）
│   └── errors/                  # 错误处理工具
└── server/                      # API 路由与业务逻辑测试
    ├── middleware/               # 中间件测试
    │   ├── session-auth.test.ts
    │   ├── csrf.test.ts
    │   ├── rbac.test.ts
    │   └── audit-log.test.ts
    ├── routes/                   # 路由层测试
    │   ├── configs/
    │   └── operation-logs/
    ├── services/                 # 业务逻辑层测试
    │   └── system/config/
    └── setup/                    # 基础设施测试（error-handlers 等）
```

## 3. Vitest 关键配置

```ts
// vitest.config.ts
export default defineConfig({
  test: {
    globals: true,       // describe/it/expect 无需手动 import
    environment: 'node',
    coverage: {
      provider: 'v8',    // 使用 v8 覆盖率引擎
      reporter: ['text', 'json', 'html'],
    },
    // 测试专用环境变量（不依赖 .env 文件，确保测试隔离和可重复性）
    env: {
      DATABASE_URL: 'mysql://root:password@localhost:3306/admin_scaffold_test',
      SESSION_COOKIE_NAME: 'auth_session',
      SESSION_TTL_DAYS: '7',
      NODE_ENV: 'test',
    },
  },
})
```

## 4. 运行测试

```bash
pnpm test          # 运行所有测试
pnpm test:ui       # 打开 Vitest UI 交互界面
pnpm test:coverage # 生成覆盖率报告
```

## 5. 中间件测试说明

项目已为四个核心中间件提供完整测试：

| 测试文件 | 覆盖中间件 | 主要验证点 |
|---|---|---|
| `session-auth.test.ts` | 会话鉴权 | 有效 / 过期 / 无效 session 处理 |
| `csrf.test.ts` | CSRF 防护 | Origin 校验、安全方法豁免 |
| `rbac.test.ts` | 权限控制 | 权限缺失拒绝、权限满足放行 |
| `audit-log.test.ts` | 审计日志 | 记录写操作、错误情况捕获 |

## 6. 编写规范

- **文件名**: 必须以 `.test.ts` 或 `.spec.ts` 结尾。
- **隔离性**: 测试用例之间不得有状态依赖，数据库测试建议使用事务回滚或独立的测试数据库。
- **Mock**: 优先使用 `vi.mock()` 处理外部服务依赖。
