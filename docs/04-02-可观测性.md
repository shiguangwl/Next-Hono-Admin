# 可观测性

> 系统的透明度是排查生产问题的关键。

## 1. 结构化日志 (Logging)

使用 **Pino** 进行日志记录，特点是 JSON 格式、高性能且易于被 ELK/HyperDX 消费。

- **全局访问**: 统一从 `@/lib/logging` 导入 logger。
- **自动附带**: 日志会自动附加 `requestId`、`sessionId` 等上下文信息。

## 2. 链路追踪 (Tracing)

- **RequestId**: 每个进入系统的请求都会在 `requestContextMiddleware` 中生成唯一的 UUID。
- **传递**: 该 ID 会通过 `AsyncLocalStorage` 在整个调用链中自动传递，并响应在 HTTP Header 的 `X-Request-Id` 中。

## 3. 审计日志 (Audit Log)

- **用途**: 记录高价值业务操作（如修改权限、删除用户）。
- **用法**: 在 Hono 路由上装饰 `auditLog` 中间件，日志会持久化到 `sys_operation_log` 表。

## 4. 可观测平台集成

项目内置了 **HyperDX (OTel)** 的全量配置：

- **配置文件**: `docker-compose.hyperdx.yml`。
- **查看指标**: 应用通过 OTLP 协议将日志、链路数据推送至 HyperDX，支持全链路时序分析。
