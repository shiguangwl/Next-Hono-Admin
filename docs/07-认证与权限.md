# 认证与权限

## 认证流程

### 登录流程

```
前端 LoginForm                → POST /api/auth/login { username, password }
  ↓
服务端 auth/index.ts
  ↓ loginRateLimit（限流检查）
  ↓ zValidator 校验参数
  ↓ 调用 login() Service
  ↓
  auth.service.ts
  ├─ findAdminByUsername(username)
  ├─ verifyPassword(input, admin.password)    // bcrypt 校验
  ├─ 检查 admin.status === 1（账号是否启用）
  ├─ updateLoginInfo(admin.id, ip)            // 更新登录 IP + 时间
  ├─ createAdminSession({ adminId, ip, userAgent })
  │   ├─ createSessionToken()                 // 生成随机 token
  │   ├─ hashSessionToken(token)              // 仅存储哈希
  │   └─ insert sys_admin_session             // 写入服务端会话表
  ├─ getAdminPermissions(admin.id)            // 获取权限列表
  └─ getAdminMenuTree(admin.id)               // 获取菜单树
  ↓
  auth/index.ts
  ├─ setSessionCookie(c, sessionToken)        // 写入 HttpOnly Cookie
  └─ 返回: { admin, permissions, menus }
  ↓
前端 useAuth.login()
  ├─ 存储 admin / permissions / menus 到 Zustand Store
  └─ 跳转到 /dashboard
```

### 认证状态初始化

```ts
// src/app/providers.tsx → AuthInitializer
// 应用启动时，通过当前 Cookie 会话调用 GET /api/auth/info 刷新认证状态
useEffect(() => {
  if (!initialized) refreshAuth();
}, [initialized, refreshAuth]);
```

```
refreshAuth() 流程：
  ├─ 直接调用 GET /api/auth/info
  │   ├─ 成功 → 更新 admin/permissions/menus
  │   └─ 失败（401/403） → 清空内存中的认证状态，设为未认证
  └─ 设置 initialized=true
```

### 会话管理

| 方面 | 实现 |
| ---- | ---- |
| 生成 | `createSessionToken()` 生成 32 字节随机 token |
| 存储 | 浏览器端使用 `HttpOnly` Cookie；服务端仅保存 `tokenHash` |
| 验证 | `sessionAuth` 查 `sys_admin_session`，校验未过期、未撤销、管理员仍启用 |
| 传递 | 浏览器请求自动携带 Cookie；非浏览器场景可兼容 `Authorization: Bearer <token>` |
| 过期 | 由 `SESSION_TTL_DAYS` 控制，默认 `7` 天 |
| Cookie 名称 | `SESSION_COOKIE_NAME`，默认 `auth_session` |

### 会话认证中间件

```ts
// src/server/middleware/session-auth.ts
export const sessionAuth = createMiddleware<Env>(async (c, next) => {
  const cookieToken = getCookie(c, env.SESSION_COOKIE_NAME);
  const authHeader = c.req.header("Authorization");
  const bearerToken = authHeader?.startsWith("Bearer ")
    ? authHeader.slice("Bearer ".length)
    : null;
  const token = cookieToken ?? bearerToken;

  if (!token) {
    c.set("admin", null);
    c.set("sessionId", null);
    c.set("permissions", null);
    return next();
  }

  const session = await authenticateSessionToken(token);
  if (!session) {
    c.set("admin", null);
    c.set("sessionId", null);
    c.set("permissions", null);
    clearSessionCookie(c);
    return next();
  }

  c.set("admin", session.admin);
  c.set("sessionId", session.sessionId);
  return next();
});

// requireAuth: 断言已认证，否则 throw UnauthorizedError
export const requireAuth = createMiddleware<Env>(async (c, next) => {
  if (!c.get("admin")) throw new UnauthorizedError();
  return next();
});
```

## RBAC 权限系统

### 数据模型

```
管理员 (sys_admin)
   ↓ 多对多
角色 (sys_role)          ← sys_admin_role 关联表
   ↓ 多对多
菜单权限 (sys_menu)      ← sys_role_menu 关联表
   └─ permission 字段    → 如 'system:admin:list'
```

### 权限加载

```ts
// src/server/middleware/rbac.ts
export const loadPermissions = createMiddleware<Env>(async (c, next) => {
  const admin = c.get("admin");
  if (!admin) {
    c.set("permissions", null);
    return next();
  }

  // 带内存缓存，避免每次请求查库
  const permissions = await getCachedPermissions(admin.adminId);
  c.set("permissions", permissions);
  return next();
});
```

### 权限校验中间件

```ts
// 校验单个权限
requirePermission("system:admin:list");

// 校验任一权限通过即可
requireAnyPermission(["system:admin:update", "system:admin:delete"]);

// 校验全部权限都通过
requireAllPermissions(["system:admin:list", "system:admin:query"]);
```

**内部逻辑：**

```ts
function checkPermission(permissions: string[], required: string): boolean {
  // 超级管理员：权限列表为 ['*']，匹配所有
  if (permissions.includes("*")) return true;
  return permissions.includes(required);
}
```

### 权限命名规范

```
格式: {模块}:{资源}:{操作}

CRUD 标准操作：
  system:admin:list      — 列表查询
  system:admin:query     — 详情查询
  system:admin:create    — 创建
  system:admin:update    — 更新
  system:admin:delete    — 删除

扩展操作（语义化命名）：
  system:admin:resetPwd    — 重置密码
  system:admin:assignRole  — 分配角色
  system:role:assignMenu   — 分配菜单
  system:log:delete        — 删除日志
```

### 菜单类型与权限

| 菜单类型         | 代码 | 说明                           | permission 字段            |
| ---------------- | ---- | ------------------------------ | -------------------------- |
| 目录 (Directory) | `D`  | 侧边栏目录，不对应实际页面     | 通常不设置                 |
| 菜单 (Menu)      | `M`  | 侧边栏菜单项，对应页面         | 可选，用于菜单显示权限     |
| 按钮 (Button)    | `B`  | 按钮级权限标识，不显示在侧边栏 | **必填**，用于操作权限校验 |

## 前端权限控制

### 页面级 — 路由守卫

```tsx
// src/app/(dashboard)/layout.tsx
// AuthGuard 包裹整个 Dashboard 布局
<AuthGuard redirectTo="/login">
  <AppShell>...</AppShell>
</AuthGuard>

// src/app/(auth)/layout.tsx
// GuestGuard 包裹认证页面，已登录则跳转
<GuestGuard redirectTo="/dashboard">
  <LoginForm />
</GuestGuard>
```

### 菜单级 — 动态菜单树

侧边栏菜单根据用户权限动态渲染（来源于 `GET /api/auth/info` 返回的 `menus` 字段），无权限的菜单不会显示。

### 按钮级 — PermissionGuard

```tsx
import { PermissionGuard } from "@/components/permission-guard";

<PermissionGuard permission="system:admin:create">
  <Button>创建管理员</Button>
</PermissionGuard>;

// 或者使用 Hook
const { hasPermission } = usePermission();
{
  hasPermission("system:admin:delete") && <DeleteButton />;
}
```

## 权限缓存策略

- `loadPermissions` 中间件使用内存缓存（Map）
- 缓存 Key：`adminId`
- 可通过 `invalidatePermissionCache(adminId)` 清除单个用户缓存
- 可通过 `invalidateAllPermissionCache()` 清除所有缓存
- 修改用户角色后应主动清除缓存
