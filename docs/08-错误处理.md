# 错误处理

## 错误类型体系

所有自定义错误继承自 `AppError` 基类，位于 `src/lib/errors/types.ts`。

```
AppError (基类)
├── UnauthorizedError    → 401  未登录或 Token 无效
├── ForbiddenError       → 403  权限不足
├── NotFoundError        → 404  资源不存在
├── ValidationError      → 400  参数验证失败
├── ConflictError        → 409  唯一性约束冲突
├── BusinessError        → 400  业务逻辑错误
├── RateLimitError       → 429  请求频率超限
├── InternalServerError  → 500  服务器内部错误（编程错误）
└── DatabaseError        → 500  数据库操作失败（编程错误）
```

### AppError 属性

```ts
class AppError extends Error {
  httpStatus: number; // HTTP 状态码
  code: string; // 业务错误码（如 'UNAUTHORIZED'）
  isOperational: boolean; // true=可预期操作错误(4xx) | false=编程错误(5xx)
  details?: unknown; // 错误详情（生产环境自动隐藏）
}
```

### 使用方式

```ts
// Service 层直接 throw，由全局错误处理器自动捕获
throw new UnauthorizedError("用户名或密码错误");
throw new ForbiddenError("无权限执行此操作");
throw new NotFoundError("管理员", id); // → "管理员 with id 123 not found"
throw new ConflictError("用户名已存在");
throw new BusinessError("不能删除自己的账号", ErrorCode.CANNOT_DELETE_SELF);
throw new ValidationError("无效的父级菜单");
throw new RateLimitError();
```

## 全局错误处理

```ts
// src/server/setup/error-handlers.ts
app.onError((err, c) => {
  // 1. HTTPException（Hono/zValidator 抛出）
  //    → 直接返回 { code: 'HTTP_ERROR', message, requestId }
  // 2. AppError 及子类
  //    → mapErrorToResponse(err, requestId)
  //    → 操作性错误(4xx): logger.warn + 返回错误信息
  //    → 编程错误(5xx): logger.error + 上报监控 + 生产环境隐藏详情
  // 3. 未知错误
  //    → logger.error + 上报监控
  //    → 生产环境: "服务器内部错误"
  //    → 开发环境: 返回原始错误信息
});
```

### 响应格式

```json
// 操作性错误 (4xx)
{
  "code": "UNAUTHORIZED",
  "message": "用户名或密码错误",
  "requestId": "abc-123"
}

// 编程错误 (5xx) — 开发环境
{
  "code": "INTERNAL_ERROR",
  "message": "Cannot read property 'id' of undefined",
  "details": { ... },
  "requestId": "abc-123"
}

// 编程错误 (5xx) — 生产环境（自动隐藏详情）
{
  "code": "INTERNAL_ERROR",
  "message": "服务器内部错误",
  "requestId": "abc-123"
}
```

## 数据库错误转换

```ts
// src/lib/errors/database.ts
export function handleDatabaseError(err: unknown): AppError {
  // MySQL 1062 唯一键冲突 → ConflictError(409)
  // MySQL 1452 外键约束失败 → ValidationError(400)
  // MySQL 1451 外键被引用   → ConflictError(409)
  // 其他数据库错误          → InternalServerError(500)
}
```

**使用方式：**

```ts
try {
  await db.insert(sysAdmin).values(data);
} catch (err) {
  throw handleDatabaseError(err); // MySQL 错误自动转为业务错误
}
```

## 新增业务错误码

1. 在 `src/lib/errors/codes.ts` 的 `ErrorCode` 对象中添加新错误码
2. 在 Service 层使用 `throw new BusinessError(message, ErrorCode.NEW_CODE)`
3. 如果需要新的 HTTP 状态码，考虑创建 `AppError` 新子类
