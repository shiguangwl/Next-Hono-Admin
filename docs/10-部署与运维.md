# 部署与运维

## Docker 部署（推荐）

### 镜像构建

项目使用**多阶段构建**，产物为 Next.js standalone 模式，镜像体积约 200MB。

```dockerfile
# 构建阶段
FROM node:23-alpine AS base     # 基础镜像
FROM base AS deps               # 安装依赖
FROM base AS builder            # 构建 Next.js (standalone)
FROM base AS runner             # 生产运行时
```

```bash
# 构建
docker build -t next-hono-admin .

# 运行
docker run -d \
  -p 3000:3000 \
  -e DATABASE_URL="mysql://user:pass@host:3306/next_hono_admin" \
  -e SESSION_COOKIE_NAME="auth_session" \
  -e SESSION_TTL_DAYS="7" \
  -e AUTO_DB_MIGRATE=true \
  -e AUTO_DB_SEED=false \
  next-hono-admin
```

### Docker Compose

```yaml
# docker-compose.yml
services:
  app:
    build: .
    ports:
      - "3000:3000"
    env_file:
      - .env.production.local # 包含真实密钥的文件（不提交到 Git）
    environment:
      - AUTO_DB_MIGRATE=true
```

```bash
docker compose up -d
```

## 手动部署

```bash
# 构建
pnpm build

# 启动（standalone 模式）
cd .next/standalone
node server.js

# 或使用 pnpm
pnpm start
```

**注意事项：**

- 需要将 `public/` 和 `.next/static/` 复制到 standalone 目录中
- standalone 模式自动包含运行时依赖，无需 `node_modules`
- 确保生产环境变量已正确配置

## 环境变量配置

### 开发环境

```env
# .env.development（已提供默认值）
DATABASE_URL="mysql://root:password@localhost:3306/next_hono_admin"
AUTO_DB_MIGRATE=true
AUTO_DB_SEED=true
SESSION_COOKIE_NAME="auth_session"
SESSION_TTL_DAYS="30"
```

### 生产环境

```env
# .env.production.local（不提交到 Git）
DATABASE_URL="mysql://prod_user:strong_password@prod-host:3306/next_hono_admin"
SESSION_COOKIE_NAME="auth_session"
SESSION_TTL_DAYS="7"
AUTO_DB_MIGRATE=true
AUTO_DB_SEED=false
```

> 首次部署时设置 `AUTO_DB_SEED=true` 初始化种子数据，之后改为 `false`。

## Next.js 配置要点

```js
// next.config.mjs
const nextConfig = {
  output: "standalone", // Docker 部署必备
  serverExternalPackages: ["mysql2"], // mysql2 不打包进 bundle
  logging: {
    incomingRequests: false, // 禁用 Next.js 默认日志，使用 Pino
  },
};
```

## 数据库运维

```bash
# 开发环境：直接同步 Schema
pnpm db:push

# 生产环境：生成 → 审查 → 执行
pnpm db:generate
git diff drizzle/                 # 审查生成的 SQL
pnpm db:migrate

# 查看数据
pnpm db:studio                    # Drizzle Studio (localhost:4983)

# 重新生成种子数据
pnpm db:seed
```

### 自动迁移机制

当 `AUTO_DB_MIGRATE=true` 时：

```ts
// src/instrumentation.ts → register()
// Next.js 启动时执行：
await ensureDatabaseInitialized()
  → runMigration()  // 执行 drizzle/ 目录下的迁移文件
  → runSeed()       // 执行种子数据（如 AUTO_DB_SEED=true）
```

## 日志

### 开发环境

使用 `pino-pretty` 格式化输出：

```bash
pnpm dev
# 输出格式: HH:MM:ss.l [LEVEL] message { requestId, method, path, status, duration }
```

### 生产环境

输出 JSON 格式日志，可对接 ELK/Loki 等：

```json
{
  "level": 30,
  "time": 1709000000,
  "msg": "GET /api/admins",
  "requestId": "abc-123",
  "method": "GET",
  "path": "/api/admins",
  "status": 200,
  "duration": "15ms"
}
```

### 审计日志

写操作（创建/更新/删除）自动记录到 `sys_operation_log` 表，包含：

- 操作模块、操作类型、操作描述
- 请求方法、URL、请求参数、响应数据
- 操作人、IP 地址
- 执行耗时、执行状态
- requestId（用于关联请求日志）
